# 실패와 개선

기대와 달랐던 사례와 바꾼 점, 다시 실행한 결과를 적는다.
아직 해결하지 못했다면 남은 문제와 다음 수정 방향을 적는다.

오류를 숨기거나 그럴듯한 내용으로 채우지 않는다.

원본 분류는 `EVAL.md` 실패 사례절에 있다. 여기서는 그 중 가르침이 큰 다섯만 옮긴다.

---

## F1. 종료 조건이 정상 작업을 끊었다

| 칸 | 내용 |
|---|---|
| 실제 입력 | `web_search`를 검색어만 바꿔 4번 호출한 브리핑 실행 |
| 기대한 결과 | 검색어를 바꿔 일하는 중이니 계속된다 |
| 나온 결과 | `maxSameToolStreak`에 걸려 `stopped`로 중단됐다 |
| 원인 | 내 코드. 도구 이름만 보고 인자를 보지 않았다 |
| 바꾼 점 | 도구+인자 지문이 같을 때만 연속으로 센다 (`agent/src/limits.ts`) |
| 다시 실행한 결과 | `done`으로 완주. 경계 검사(인자 다르면 진전)도 붙였다 |

- 증거: `agent/test/limits-usage.test.ts` 「같은 도구라도 인자가 다르면 진전이다」

## F2. 중단된 실행의 비용을 $0.0000으로 보고했다

| 칸 | 내용 |
|---|---|
| 실제 입력 | 결과 메시지를 못 받고 끝난 실행의 사용량 집계 |
| 기대한 결과 | 모른다고 표시한다 |
| 나온 결과 | 비용 $0.0000 — "안 들었다"는 거짓 보고. 실제로는 캐시 읽기 58,094 토큰을 썼다 |
| 원인 | 내 코드. `usage_known`을 무조건 참으로 뒀다 |
| 바꾼 점 | 결과 메시지를 못 받으면 `usage_known: false` (`agent/src/usage.ts`, `engine.ts`) |
| 다시 실행한 결과 | "확인 못 함"으로 표시된다. V6 상한 중단 2건에서 같은 문구 확인 |

- 증거: `agent/test/limits-usage.test.ts` 사용량 집계절

## F3. 지어낸 근거 카드를 서버가 거절하고 모델이 회복했다 (live-t1)

| 칸 | 내용 |
|---|---|
| 실제 입력 | 4번 카드 `sources`에 실행 기록에 없는 `get_user_metrics` 값 인용 |
| 기대한 결과 | (당시) 통과 후 사람이 검수에서 잡는다 |
| 나온 결과 | `source_not_found`로 거절. 모델이 `get_user_metrics`를 재호출하고, 그래도 안 되자 개발 활동 내용으로 카드를 바꿔 완성했다 |
| 원인 | 모델이 기억으로 근거를 적었다. P1-7(a) 대조가 없었다면 카드로 굳었을 것이다 |
| 바꾼 점 | `compose_card` sources 존재 대조 (`mcp-server/src/chart.ts` `verifySourceRow`, cover 제외) |
| 다시 실행한 결과 | live-t2에서 GHSA ID를 `field`에 넣은 2건이 `invalid_source_field`로 거절되고 같은 방식으로 회복했다 |

- 증거: `runs/live-t1/toolcalls.jsonl` (gitignore라 로컬에만), `mcp-server/test/source-verification.test.ts` compose절

## F4. 사용자 지표 축 전체가 빈다 (live-t1)

| 칸 | 내용 |
|---|---|
| 실제 입력 | live 첫 실행의 `get_user_metrics` 호출 |
| 기대한 결과 | 7일 series + totals + 직전 기간 비교값 |
| 나온 결과 | `rpc_not_created` — 집계 함수가 Supabase에 없었다 |
| 원인 | 환경. `supabase/ops_metrics.sql`을 실행하지 않았다 (코드 문제가 아니다) |
| 바꾼 점 | 고칠 코드가 없다. 사람이 SQL Editor에서 실행하고 토큰을 맞췄다 |
| 다시 실행한 결과 | `smoke-live` 3번 + 직접 호출로 집계 반환 확인. 전부 0·직전 활성 1 — 실제 0이지 결측이 아니다 |

- 증거: `RUN.md` live 실행절, `DECISIONS.md` D24

## F5. 셰도잉 감시가 정상 설정을 실패시켰다

| 칸 | 내용 |
|---|---|
| 실제 입력 | 읽기 도구 7개를 `allowedTools`에 넣은 정상 실행 |
| 기대한 결과 | 통과한다 (읽기 자동 승인은 의도한 설계다) |
| 나온 결과 | SDK 경고를 보고 전부 실패 처리했다 |
| 원인 | 내 코드. 경고 자체를 사고로 봤다 |
| 바꾼 점 | 경고에서 도구 목록을 파싱해 **쓰기 도구가 가려진 경우만** 실패 (`agent/src/shadowguard.ts`) |
| 다시 실행한 결과 | 정상 실행됨. 경계 검사(읽기만 가려진 것은 통과)를 짝지었다 |

- 증거: `agent/test/shadowguard.test.ts`
