## 무엇을 해결하는가

앱을 하나 배포해 두면 매주 같은 점검을 반복한다 — 배포가 깨지지 않았는지, 함수가 오류를 내지
않는지, 사용자가 늘고 있는지, 열어 둔 이슈가 쌓이고 있는지, 쓰는 라이브러리에 보안 권고가 뜨지
않았는지.

문제는 **이 넷이 서로 다른 화면에 흩어져 있다**는 것이다. 네 곳을 각각 열어야 하고, 각 화면은
숫자를 보여주지만 "지금 중요한 게 무엇인지"는 말해 주지 않는다. 그래서 며칠씩 안 열어 보고,
그동안 문제는 아무 소리 없이 지나간다.

**이 서비스가 겨냥하는 실패는 틀린 답이 아니라 조용한 실패다.** 오류율이 올라가도 아무도 말해
주지 않는 상태를, 매주 한 번 사람이 읽을 수 있는 형태로 바꾼다.

각 카드는 셋 중 하나다: **지금 손봐야 할 것** · **지켜볼 것** · **알아둘 것**.

핵심 제약 하나 — **근거 없는 수치를 카드에 넣지 않는다.** 운영 판단의 근거가 되는 문서이므로
환각은 곧 기능 실패다. `EVAL.md`에서 환각률을 첫 번째 지표로 잰다.

쓰기 도구는 에이전트가 직접 실행하지 못한다. 제안만 만들고, 사람이 승인해야 실행된다.
삭제 권한은 어떤 도구에도 없다. Agent SDK 내장 도구(`Bash`·`Write`·`Edit` 등)는 차단한다.
자세한 스키마와 실패 규칙은 `TOOLS.md`.

### 승인 게이트는 세 겹이다

Agent SDK 문서가 경고하듯 **자동 승인된 도구는 `canUseTool` 콜백에 도달하지 않는다.** 도구를 모두
허용 목록에 넣으면 승인 화면이 아예 뜨지 않는다 — 게이트가 있는 줄 알았는데 없는 상태다.
그래서 세 겹으로 막았다.

1. MCP 서버가 쓰기 도구에 `_meta["anthropic/requiresUserInteraction"]`를 선언 → allow 규칙이
   매치돼도 항상 승인 콜백으로 떨어진다. **게이트가 앱 설정이 아니라 도구의 성질이 된다.**
2. MCP 서버가 1회용 `approval_token`을 검사 → 앱을 우회해 서버에 직접 붙어도 막힌다.
3. `PreToolUse` 훅이 **설정과 무관한 불변식 두 개**를 검사 → 모든 단계보다 먼저 실행되고,
   훅의 deny는 `bypassPermissions`에서도 유효하다. 허용 목록 밖의 도구, 그리고 **모델이 스스로
   넣은 `approval_token`** 을 거절한다. (훅은 `canUseTool`보다 먼저 돌기 때문에 "승인 기록이
   있는지"는 검사하지 않는다 — 거기서 막으면 사람이 묻기도 전에 모든 쓰기가 차단된다.)

덤으로 자체 검사가 하나 생겼다. 콜백이 가려지면 SDK가 `CLAUDE_SDK_CAN_USE_TOOL_SHADOWED` 경고를
띄우므로, 이를 잡아 **실패로 처리**한다. 자세한 근거는 `DECISIONS.md` D14.

핵심 판정은 원고를 읽어 확인했다.

- `f3` — 지표가 급감했지만 **원인을 단정하지 않았다**: *"원인은 이 데이터로 확인 못 함"* 3곳,
  해석은 *"추정"* 으로 표시, 시각이 겹치는 배포를 원인으로 지목하지 않음. 3/3 통과.
- `f4` — **결측과 0을 구별했다**: *"함수 오류 수: `null` → 확인 못 함 (0건이 아니라 조회 자체가
  안 됨)"*. 그리고 카드를 5~8장 억지로 채우지 않고 **4장으로 줄였다**.

### 세팅 변화 실험

| # | 바꾼 것 | 결과 |
|---|---|---|
| E4 | 프롬프트에서 `확인한 사실 / 추정 / 확인 못 함` **3분류 지시를 뺐다** | **형식에는 강한 효과** — 사실 분류 표시가 f3 27→3회, f4 26→7회. `확인한 사실`·`확인 못 함`은 6시행 전부 0회. **내용은 유지** — 결측과 0 구별, 원인 단정 회피가 살아 있었다 |
| E2 | `render_chart` 의 `source` 검사 해제 | **실행하지 않았다.** E0 에서 그 검사가 한 번도 발동하지 않아(차트 28회 중 `source_mismatch` 0회) 판정이 불가능함을 먼저 확인했다 |

E4 에서 얻은 것: 이 지시의 값은 **읽는 사람이 감사할 수 있는 형태**에 있다. 지시를 빼도 모델은
같은 판단을 했지만, 어느 문장이 사실이고 무엇을 모르는지를 읽는 사람이 문맥에서 추론해야 한다.
과잉 단정은 6시행에 네 곳 늘었으나 표본이 작아 경향으로만 적는다.

**같은 코드·모델·픽스처인데 결과가 갈린다.** f1 의 필수신호가 1/3 · 3/3 · 2/3, f2 의 비용이
최소·최대 두 배 차이다. 그래서 **1회 값을 근거로 쓰지 않는다.** 편차와 한계는 `EVAL.md` 에 적었다.

⚠️ **지표 값 환각률이 0이라고 말하지 않는다.** 그 규칙은 12시행에서 진짜 환각 0건, 허수 9건을
냈고 그 과정에서 계속 좁혔다. 지금의 0은 "잡지 못한 것"과 구별되지 않아 **후보로만** 보고한다.
확실하게 말할 수 있는 것은 **식별자 환각 0건**(배포 ID·커밋 SHA·이슈 번호, 정확한 문자열 일치)이다.

## 남은 과제

검토한 뒤 **의도적으로 미룬** 범위다. 못 한 것이 아니라 판단한 것이다.

| 미룬 것 | 왜 | 넣으려면 |
|---|---|---|
| **마케팅 사용자 분석** (화면 전환율·유입 경로) | 대상 앱에 계측이 전혀 없어(의존성은 Supabase·Next·React뿐) 읽어올 데이터가 존재하지 않는다. 기반 앱을 고쳐야 하고, 심어도 며칠치만 쌓인다 | `app_events(경로·유입원·단계·시각)` 테이블 + 기반 앱 계측 → 집계 RPC로 전환율 계산. 데이터가 몇 주 쌓인 뒤 축 하나로 추가 |
| **n8n 다중 소스 오류 감지** | 인스턴스가 로컬이라 노트북이 꺼지면 멈춘다. "사람이 시작하지 않아도 도는" 감시가 되려면 호스팅이 필요하다 | n8n Cloud 또는 자체 호스팅 → 주기 감시 후 앱 웹훅 호출 |
| **자동 트리거** (스케줄·웹훅) | 배포하지 않으므로 스케줄이 돌 자리가 없다 | 배포하거나 로컬 스케줄러로 시연 |
| **멀티 에이전트** (조사→작성→검토) | `AGENT_LOOP.md`에 역할 분리 설계는 있으나 이번 범위에서 구현하지 않았다 | 검토 에이전트를 붙여 환각·누락을 잡게 하고, 환각률 변화를 실험으로 측정 |

## 밝혀 두는 것

- 평가 세트는 **합성 운영 스냅샷 4개**다. 실제 운영 데이터로 측정한 결과가 아니다.
- 기준 시각과 외부 API 응답은 평가 실행에서 **픽스처로 고정 주입**한다. 실제 API를 쓰면 실행
  시점마다 결과가 달라져 세팅 변화의 효과를 판정할 수 없기 때문이다.
- **실행은 두 자격증명 중 하나로 돈다.** `ANTHROPIC_API_KEY` 가 있으면 그것으로(API 사용량
  크레딧에서 차감), 없으면 SDK 가 저장된 로그인(구독)으로 시도한다. 화면과 CLI 가 어느 쪽인지
  함께 적는다 — 같은 금액이 두 지갑에서 다른 뜻이기 때문이다. 자세한 근거는 `DECISIONS.md` D18.
- **화면에 표시하는 비용은 클라이언트 측 추정값이다.** Agent SDK가 번들된 단가표로 로컬 계산하며,
  단가 변경이나 모델 미인식 시 실제 청구와 어긋날 수 있다. 공식 문서도 이 값으로 재무 결정을 내리지
  말라고 명시한다. 종료 조건과 참고용 표시에만 쓴다.
- 크래시나 예산 초과로 끝난 실행은 비용 필드가 0이거나 빠질 수 있다. 그런 경우 0으로 적지 않고
  **`usage_known: false`로 표시**한다. 사용량을 모르는 것과 0인 것은 다르다.
- 표지 삽화는 **설명용 생성 이미지**다. 실제 화면 캡처가 아니다.
- 도구 권한 제한은 MCP 서버와 코드의 검사이며 운영체제 샌드박스가 아니다.
- 실제 API 키·토큰은 이 저장소에 없다. `.env.local`은 제외했고 예시 파일은 형식만 담는다.
